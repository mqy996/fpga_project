# ADC frame-start diagnosis

适用：并行多通道ADC中物理输入与主机通道呈固定循环偏移，尤其在上一帧读取与下一帧转换重叠时。先读目标ADC手册确认BUSY、CS/RD、首字标志和结果更新时刻；本案例不能替代其它器件的时序规格。

1. 建立物理映射：ADC实例、V1～V8、板级CH1～CH24、主机CH00～CH23。对单一路输入明显不同的已知信号，保留其余输入的状态。固定偏移是时序假说的线索，不足以排除接线/通道打包错误。
2. 同步观察CONVST、BUSY、CS、RD、数据总线、读索引和FRSTDATA。先确认何时结果寄存器更新，再确认何时读取首字。若没有这组板上同步波形，应明确物理根因仍缺波形闭环。
3. 本工程修复将读帧起点从下一次CONVST改为本次同步BUSY下降沿，并把索引归零；下一次转换仍按节拍发生，保留转换/读取流水。不要把关闭流水或软件移动通道号当作同等修复。
4. 为每个通道赋唯一测试码，覆盖连续转换。检查V1的FRSTDATA高、V2～V8低；故意给错首字应拒收而不是产生有效采样组。三片均有效才合并整组。
5. 分别计算BUSY宽度、RD脉宽、首字延迟、最后读出到下一次结果更新的余量；使用真实时钟和该器件最差条件。仿真周期余量不能写成实测模拟性能。

案例证据：task004的定向仿真为12帧连续1MSPS、32MHz域32周期节拍、BUSY高21周期，最后RD下降至下一BUSY下降至少7周期（约219ns），首字FRSTDATA故意为低时拒收；用户逐路输入确认通道顺序正确。原工程路径为`results/task004/validation.md`及`Archive/task-004-adc-pipeline-frame-alignment/`。这些是案例来源，不是本独立包所需依赖。

失效条件：其它ADC无FRSTDATA、串行/DDR接口、BUSY语义不同、读取过程不能与转换重叠、跨域多位数据未经稳定窗口保护。此时保留“结果更新 → 帧首确认 → 唯一码验证”的方法，重新建立契约，不能复制本例周期或引脚。

已验证的改善是通道对应关系和拒收路径；没有同口径旧设计实测，不声称提升吞吐倍数或降低资源百分比。
